## The ticket

[#67](https://github.com/grimfeld/synesis/issues/67)

Found in the 2026-11-03 code audit; still present on `integrate/specs-32-35` (2d4cc50).

**Floating Action tags hold the signing key.** Every third-party Action in `.github/workflows/release.yml` and `ci.yml` is pinned to a tag that can be moved: `tauri-apps/tauri-action@v0`, `softprops/action-gh-release@v2`, `signpath/...@v3`, `dtolnay/rust-toolchain@stable`, `Swatinem/rust-cache@v2`, and others. `tauri-action@v0` receives `TAURI_SIGNING_PRIVATE_KEY` and a `GITHUB_TOKEN` with `contents: write`. If that tag is moved to malicious code (as happened to tj-actions/changed-files in 2025), the attacker can publish a signed update that every installed desktop app installs.

**No test gate.**
- `release.yml` checks the version, tags, publishes and builds, but runs no tests and does not wait for CI on that commit.
- `scripts/release.mjs` does not check for a clean working tree, that HEAD matches `origin`, or that the branch is `main`; another branch only gives a warning in the workflow.
- `release.mjs` accepts any version, including a lower one. A typo such as `0.0.3` for `0.0.30` publishes an older "latest", and installed apps stop updating until another release.

**Fix.**
- Pin every third-party Action to a full commit SHA with the version in a comment, and add `.github/dependabot.yml` for `github-actions`.
- In the `version` job, require CI to have passed on `$GITHUB_SHA` (or run `cargo test --workspace` and `npm run test:unit` there).
- Make any branch other than `main` an error unless the version has a prerelease suffix.
- In `release.mjs`, refuse a dirty tree, a branch out of step with `origin`, or a version that is not greater than the current one.

## Release and CI (#67, #77)
- **Action pins.** Every third-party action is pinned to a commit SHA, with its version in a comment. The same major versions as before.
- **Fewer third-party actions.** `softprops/action-gh-release` is replaced by `gh release upload`.
- **Dependabot.** Proposes weekly bumps for actions, cargo, npm and `site/` npm.
- **Token permissions.** Both workflows default to a read-only token. Only jobs that write ask for `contents: write`; `version` and `windows` (SignPath) also get `actions: read`.
- **Git credentials.** Every checkout sets `persist-credentials: false` except the `version` job's, which pushes the tag.
- **CI gate.** The `version` job waits for `ci.yml` to pass on the commit before it tags anything (75 min limit). It also refuses a ref other than `main` unless the version is `X.Y.Z-pre`.
- **Draft release.** The release is created as a draft, and the build jobs upload to it by `releaseId`.
- **Publish job.** A new `publish` job makes the release public only when:
  - the desktop, Windows, Windows-manifest and Android jobs all passed;
  - `latest.json` has darwin-aarch64, darwin-x86_64, linux-x86_64 and windows-x86_64;
  - the APK is attached.

  Otherwise the release stays a draft. The landing-page rebuild now runs after `publish`.
- **Android signing.** Keystore passwords go through `env:`, not the command line.
- **`npm run release` refuses:**
  - a working tree with uncommitted changes;
  - a branch other than `main` (a `-pre` version may come from any branch);
  - HEAD != `origin/<branch>`;
  - a version that is not greater than the current one (semver comparison).

  It now also bumps `package-lock.json`.
- **New CI steps:**
  - `cargo fmt --check`;
  - `cargo test --workspace --exclude web`, so the src-tauri tests now run;
  - `release.mjs --check`;
  - an audit job: `cargo audit` plus `npm audit --omit=dev --audit-level=high` for the app and `site/`.
- **wasi-sdk checksum.** `build-web.mjs` checks the tarball's SHA-256 before unpacking it.
- **Updater key.** The updater pubkey is untouched.
